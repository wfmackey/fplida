Home Affairs Dataset Explainer

Internal fplida note on HA/DHA migration, traveller, visa, and AMEP products

Published

June 16, 2026

1 Purpose and evidence standard

This note covers the Department of Home Affairs migration products in the current PLIDA metadata. The metadata supplier code is HA; this guide treats the user’s “DHA” shorthand as the same Home Affairs source group.

Schema and value-domain claims below are deliberately labelled by evidence level:

Evidence label Meaning
Official Backed by an official public source linked in this guide.
Local generator Observed in the current fplida generator, tests, PLIDA metadata, or foundation files. Useful for implementation, but not a real-world calibration target unless separately sourced.
Unresolved No official source or local code evidence was found in this pass. Do not use as a calibration fact.

3 Source-backed coverage decisions

SDB permanent migrants Home Affairs settlement reporting pages and the SDB data dictionary are the official anchors for settlement-record scope and SDB field/code interpretation. I did not find a public source in this pass that proves the generated SDB category distributions or maps every generated Home Affairs compact value to an official code label.

5 Variable-level schema register

Every generated variable observed in this pass for this guide is listed in schema-registers/schema-register-home-affairs.csv. The register records R type, sampled generated missingness, sampled generated domains/distributions, and direct PLIDA metadata matches. Treat those sampled domains/distributions as implementation evidence only, not as official source data.

A rendered variable evidence appendix for this guide is available at variable-evidence-appendices/home-affairs-variable-evidence.qmd. It contains one row per generated variable with observed generated values or distributions, local metadata/crosswalk status, and unresolved-source caveats.

A stricter source-audited variable-code evidence register is available at home-affairs-variable-code-evidence.csv, with a rendered companion note at home-affairs-variable-code-evidence.qmd. Use that register to distinguish official SDB/AMEP concept support, local PLIDA/generator evidence, and public-codebook-not-found rows.

6 Generated schema and value domains

6.1 AMEP

The local AMEP generator writes only a compact client/English product. The local tests establish the hour and ASLPR ranges; those ranges should not be treated as real AMEP distributions without checking the AMEP source paper or source microdata documentation.

Variable Type Expected values or distribution Evidence
SYNTHETIC_AEUID Character ID Home Affairs agency person key; non-missing for generated rows. Local generator
YEAR_OF_BIRTH Integer Source spine birth year for eligible overseas-born persons. Local generator
HOURS_TOTAL Numeric Tested generated range 50 to 510 hours. Local generator; compacted from same-dataset AMEP year/quarter hours metadata such as AMEP_2003 and AMEP_2019_Q2; official distribution still required for calibration
ASLPR_SPEAKING_INITIAL, ASLPR_LISTENING_INITIAL, ASLPR_READING_INITIAL, ASLPR_WRITING_INITIAL Integer Tested generated scores 0 to 5. Local generator; same-dataset AMEP metadata crosswalks to INITIAL_ASLPR_SPEAK, INITIAL_ASLPR_LISTEN, INITIAL_ASLPR_READ, and INITIAL_ASLPR_WRITE
ASLPR_SPEAKING_LATEST, ASLPR_LISTENING_LATEST, ASLPR_READING_LATEST, ASLPR_WRITING_LATEST Integer Tested generated scores 0 to 5; latest is intended to be no worse than initial in the synthetic process. Local generator; same-dataset AMEP metadata crosswalks to LATEST_ASLPR_SPEAK, LATEST_ASLPR_LISTEN, LATEST_ASLPR_READ, and LATEST_ASLPR_WRITE
ENROLMENT_YEAR Integer Synthetic program enrolment year; generated from arrival and age logic. Local generator; same-dataset AMEP metadata crosswalk to ENROLLED_FY

AMEP gaps: the current implementation does not separately generate the metadata-listed AMEP activity, address, award-code, award, or full English module schemas. Local metadata contains initial/latest ASLPR variables, but I did not locate a public score-label/distribution source in this pass.

6.4 Travellers

The local traveller product is a status summary, not raw border movement episodes.

Variable Type Expected values or distribution Evidence
SYNTHETIC_AEUID Character ID Home Affairs agency person key. Local generator
ERP_STATUS_QUARTERLY Integer vector/string Rust constants map quarterly status to 1 = resident present, 2 = resident absent, 3 = not resident. Local generator; compacted from same-dataset ERP_STATUS_YYYYQn metadata columns
PP_STATUS_QUARTERLY Integer vector/string Same local status code domain as ERP status. Local generator; simplified compact form of same-dataset PP_STATUS_YYYYMn and census-night PP metadata columns

Traveller gap: local PLIDA metadata confirms wide ERP/PP status-column concepts, but no official public codebook was located in this pass for the generated 1/2/3 quarterly status encoding. Use the local constants only for fplida implementation checks.

7 Research uses and limits

These products are useful for testing migration linkages, migrant cohorts, visa-to-settlement histories, and migrant-specific service use in later fplida builds. They are not yet strong calibration products. In particular, SDB, visa subclass/report group, IELTS, occupation, and traveller status codes need source-backed code tables before they are used for research-facing examples.

8 Build implications

  1. Keep Home Affairs products parquet-only unless a downstream package consumer requires CSV.
  2. Add regression tests for all generated HA products, not only AMEP, before promotion.
  3. Treat local category domains as implementation contracts, not official statistical domains, unless the relevant Home Affairs dictionary is linked directly in the variable table.
  4. For future synthetic builds, add a separate evidence file mapping SDB and visa codes to the official Home Affairs data dictionary/code tables.

9 Validation checks to add

Check Evidence basis
AMEP hours remain within tested range 50 to 510. Local test.
ASLPR fields are integers 0 to 5 and latest scores do not decline unless a real source says decline is possible. Local test plus program logic; local AMEP metadata confirms ASLPR field concepts but not generated distributions.
SDB date consistency: DATE_OF_GRANT >= ARRIVAL_DATE where the synthetic design intends grant after arrival. Local generator.
Visa dates: grant date should not precede lodged date. Local generator.
Traveller quarterly status values must remain within local constants 1, 2, 3. Local Rust constants.
