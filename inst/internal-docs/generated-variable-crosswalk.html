Generated Variable Crosswalk

Generated fplida columns versus local PLIDA/BLADE metadata

Published

June 16, 2026

1 Purpose

generated-variable-crosswalk.csv is the audit table for all generated columns currently listed in generated-schema-register.csv. It does not assert that a candidate is correct unless the status says the row is directly matched or has a manual same-dataset crosswalk. It records the evidence status for each generated column so unresolved implementation fields stay visible.

6 Use Rule

Rows with direct_* status can be treated as local metadata-backed generated fields. Rows with manual_same_dataset_plida_concept_match are local crosswalks from generated names to same-dataset PLIDA metadata variables, but they still should not be presented as official source variable names. Rows with generated_compact_from_same_dataset_metadata or generated_derived_from_same_dataset_metadata are implementation fields backed by local metadata concepts, not literal source columns. Rows with unresolved_*, external_source_concept_not_source_equivalent, or local_generator_not_source_equivalent must remain labelled as implementation-only or not-source-equivalent until stronger evidence is found.
