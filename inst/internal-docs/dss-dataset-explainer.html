5 Variable-level schema register

Every generated variable observed in this pass for this guide is listed in schema-registers/schema-register-dss.csv. The register records R type, sampled generated missingness, sampled generated domains/distributions, and direct PLIDA metadata matches. Treat those sampled domains/distributions as implementation evidence only, not as official source data.

A rendered variable evidence appendix for this guide is available at variable-evidence-appendices/dss-variable-evidence.qmd. It contains one row per generated variable with observed generated values or distributions, local metadata/crosswalk status, and unresolved-source caveats.

A stricter source-audited variable-code evidence register is available at dss-variable-code-evidence.csv, with a rendered companion note at dss-variable-code-evidence.qmd. Use that register to distinguish DOMINO/DEX public concept support, local PLIDA/generator evidence, and public-codebook-not-found rows.

Dataset Generated variable rows Direct PLIDA metadata matches No direct PLIDA name match
DEX 14 2 12
DOMINO 130 128 2

Rows without a direct PLIDA match need a generated-name to DIL-name crosswalk before they are treated as source variables. generated-variable-crosswalk.csv now maps all twelve compact DEX no-direct-match fields to same-dataset DEX metadata variables, and maps the two generated DOMINO death date components back to DATE_OF_DEATH. Those mappings do not supply official code labels; they only establish the local DIL/source-variable concept.

8 Research uses and limits

DOMINO is the main welfare/social-security longitudinal product. It can support spell construction, benefit histories, housing/education context, and payment-history examples. DEX is currently suitable for service-interaction examples and SCORE mechanics, but not for detailed DEX program taxonomy until assistance-type and exit-reason codebooks are linked.

9 Build implications

  1. DOMINO code values should stay close to the DSS Aristotle registry; add variable-level links for high-use benefit, component, and end-reason codes.
  2. DEX should not be used as a general welfare receipt source; use DOMINO for payments and DEX for service sessions/outcomes.
  3. Add explicit tests for DEX category domains beyond SCORE once a DEX code table is sourced.
